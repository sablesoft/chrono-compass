# План внедрения мобильной версии

Статус: Draft (рабочий документ)
Ответственный: Product/Frontend
Область: адаптация UI ChronoCompass под мобильные устройства

## Цели
- Сделать приложение удобным на экранах телефонов без горизонтального скролла.
- Сохранить ключевые интеракции с колесами на тач-устройствах.
- Не ломать desktop UX.
- Внедрять поэтапно с понятными критериями готовности.

## Что не входит в задачу
- Без изменений математики/движка колес.
- Без редизайна фич за пределами адаптивности и эргономики взаимодействия.
- Без полной смены визуальной темы.

## Брейкпоинты
- Phone: `<= 640px`
- Tablet: `641px - 1024px`
- Desktop: `> 1024px`

## Текущие проблемные точки (по ревью кода)
- Главный контейнер форсит desktop-ширину в `src/App.svelte` (`clamp(1200px, ...)`).
- Сетка доски стартует с N колонок в `src/components/Board.svelte`.
- В `src/components/Header.svelte` нет явного mobile-layout.
- Панели колес (`Compass/Cycle`) используют desktop-плотность и размеры.
- Тултипы заточены под desktop-поповеры, что неудобно на тач-экранах.

## Техническое направление
- Mobile-first стратегия в CSS.
- Сохранение текущей структуры компонентов.
- Добавление compact-режимов по брейкпоинтам.
- Для телефонов: sheet-представление деталей там, где floating tooltip неустойчив.
- Для desktop: переход к модели **Resizable Dashboard Grid (masonry-like)** с сохранением размеров карточек.

## Обязательные продуктовые требования
1. Все тултипы в мобильной версии раскрываются на весь экран.
2. Один экран = одна карточка колеса.
3. Все колеса доски размещаются в циклической карусели.
4. Переключение колес: по горизонтальным кнопкам и горизонтальным свайпом.
5. В хедере карточки размещаются 2 отдельные кнопки collapse/expand:
   - кнопка для визуального квадрата;
   - кнопка для инфоблока;

## Поэтапный план

### Этап 1: Каркас приложения и сетка доски
- Обновить контейнер в `src/App.svelte` на fluid-layout для малых экранов.
- Для мобильной версии заменить сетку доски на режим «1 карточка на экран».
- Реализовать карусель колес с циклической навигацией по кругу.
- Добавить два способа переключения: кнопки влево/вправо и горизонтальный свайп.

Критерии приёмки:
- Нет горизонтального скролла на ширинах 360-430px.
- На телефоне одновременно видна только одна карточка колеса.
- Карусель циклическая: после последнего колеса переход к первому и наоборот.
- Переключение работает и по кнопкам, и по свайпу.

### Этап 2: Header и глобальные контролы
- Внедрить mobile-layout для `Header.svelte` (компактные logo/title, перенос контролов).
- Обеспечить доступность `ProfilePicker`, `TimePicker` и `LocationPicker` без наложений.
- Проверить тач-эргономику кнопок действий.

Критерии приёмки:
- Header стабилен при скролле.
- Контролы не обрезаются и не перекрываются на phone-width.

### Этап 3: Адаптивность карточек колес (Compass/Cycle)
- Добавить compact-режим типографики и отступов в info-блоках.
- Подогнать кластеры кнопок (nav/toggles) под удобные тач-зоны.
- Проверить usability SVG-интеракций на coarse pointers.

Критерии приёмки:
- Основные действия с колесом доступны одной рукой.
- Нет конфликтов между контролами и областью графика.

### Этап 4: Mobile UX для тултипов и модалок
- Добавить phone-поведение для `CompassTooltip` и `CycleTooltip`.
- В мобильной версии тултипы открываются в fullscreen-режиме (на весь экран).
- Проверить mobile-layout модалок (`WheelControl`, `WheelPicker`, `LocationPicker`, `MomentControl`) и поведение с виртуальной клавиатурой.

Критерии приёмки:
- Панели деталей читаемы и скроллятся на телефонах.
- Любой tooltip на телефоне занимает весь экран и корректно закрывается.
- Фокус в input не ломает верстку (включая keyboard resize).

### Этап 5: Производительность и полировка
- Проверить стоимость анимаций и blur/shadow на мобильных GPU.
- При необходимости упростить тяжелые эффекты в compact-режиме.
- Финальный проход по accessibility (tap targets, focus, contrast, semantics).

Критерии приёмки:
- Плавная работа на современных мобильных браузерах.
- Базовые требования доступности соблюдены для touch + keyboard.

## Матрица тестирования
- Устройства:
  - iPhone (Safari)
  - Android (Chrome)
  - Desktop (Chrome/Firefox/Safari)
- Ширины:
  - 360, 390, 430, 768, 1024, 1280+
- Сценарии:
  - 1 колесо, 4+ колес на доске
  - Открытие тултипа с длинным контентом
  - Многократное открытие/закрытие модалок
  - Редактирование времени/локации, добавление/редактирование колес

## Риски
- Конфликты layering между sticky-header, tooltip и modal.
- Различия поведения viewport resize при клавиатуре (iOS vs Android).
- Просадка производительности из-за тяжелых эффектов на старых телефонах.

## Открытые вопросы
