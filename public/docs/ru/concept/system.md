# System Wheel

System Wheel — это тип колеса, который описывает **многотельное представление орбитальной системы** в общей compass-подобной системе координат.

Оно использует ту же визуальную грамматику, что и Compass Wheel, но с другой физической семантикой.
Вместо локального горизонта здесь объединяются:

* **синодическая фазовая геометрия** (угловое положение по окружности),
* **геометрия расстояний** (радиальное положение),
* **знак эклиптической широты** (north/south относительно плоскости эклиптики).

System Wheel — это не про локальную видимость.
Это про **структуру системы вокруг выбранного focus**.

---

## На какой вопрос отвечает?

Для выбранного момента `t` и выбранной системы отсчёта (`looker`, `focus`):

* Где находится каждая цель по фазе в системе прямо сейчас?
* Какие тела находятся north/south относительно плоскости эклиптики?
* На каком расстоянии каждая цель от тела-focus?
* Как каждое тело движется вдоль своей текущей орбитальной дуги?

Коротко:

> Как выглядит эта орбитальная система прямо сейчас в едином представлении?

---

## Базовая концепция

System Wheel — это **составное колесо**, которое строится из нескольких cycle-движков.

Для каждой цели:

* угол вычисляется из синодической фазы (`synod`),
* базовые точки орбиты берутся из спиц текущего synod-цикла,
* дополнительные точки формы берутся из одного или нескольких `bind`-циклов в том же временном окне,
* добавляются точки перехода через плоскость эклиптики для корректного стилевого разделения линии.

Это даёт стабильный и сопоставимый трек орбиты, который можно отрисовать в одном общем колесе для множества тел одновременно.

---

## Сущности и обязательные атрибуты

System Wheel требует три группы ролей:

* **looker** — источник опорного направления для синодической фазы
* **focus** — центральное тело отображаемой системы
* **targets** — одно или несколько тел, отображаемых на колесе

Локальная топоцентрическая позиция наблюдателя для геометрии system-колеса не требуется.

---

## Геометрическое отображение

### Угловое отображение (phase)

Угол маркера цели вычисляется из синодической фазы в выбранной системе отсчёта.

Ориентация колеса сохраняет compass-стиль интерфейса, чтобы взаимодействие оставалось единым с шаблоном Compass UI.

### Радиальное отображение (нормализация расстояний)

Исходные расстояния измеряются в AU от **focus → target**.

Чтобы много тел читались в одном колесе, радиус нормализуется относительно самой дальней доступной точки в текущем наборе расчёта:

* собираются расстояния текущих положений и точек их orbit track,
* находится `maxDistance`,
* радиус каждой точки задаётся как `distance / maxDistance`.

В результате:

* самая дальняя доступная точка имеет orbit `1`,
* все остальные точки пропорционально размещаются внутри этого диапазона.

### Вертикальный семантический канал (Ecl)

Для каждой точки также вычисляется эклиптическая широта (`Ecl`):

* `Ecl >= 0` → **north**
* `Ecl < 0`  → **south**

Этот знак используется для разделения стиля дуг (сплошная/штриховая) и для семантики в тултипах.

## Спицы, треки и узлы

Трек в System Wheel строится по целям послойно:

1. **Synod spokes** (главные структурные узлы)
2. **Bind-узлы** в окне текущего synod-цикла (уточнение формы)
3. **Узлы уплотнения** при слишком большом угловом зазоре между соседними точками
4. **Seam-узлы** в местах пересечения плоскости эклиптики для точных переходов стиля

Политика merge удерживает приоритеты детерминированно:

* узлы границ цикла (`E`, `E+`, `E_next`) сохраняются,
* seam-узлы приоритетнее обычных,
* главные спицы приоритетнее близких вторичных точек.

Это устраняет визуальную неоднозначность и сохраняет стабильные навигационные якоря.

---

## Семантика данных в UI

System Wheel использует отдельные подписи:

* **Phase** — угловая фазовая позиция
* **Ecl** — эклиптическая широта в градусах
* **north / south** — знак эклиптической широты
* **Dist to &lt;focus&gt;** — расстояние от focus до target

Эти подписи формируются на уровне solver, поэтому шаблон Compass может отображать разные типы колёс без жёстких Earth/horizon-допущений.

---

## Модель взаимодействия

System Wheel использует compass-шаблон взаимодействия:

* hover/click по маркерам и кластерам,
* pin тела,
* просмотр orbit nodes,
* переход к моментам узлов,
* double click по поддерживаемым узлам/спицам для навигации по времени.

Если тело закреплено (pinned), навигация по спицам резолвится в соответствующие узлы орбиты этого тела в контексте текущего цикла.

---

## Чем System отличается от Compass Wheel

**Compass Wheel** — топоцентрическое и локально-наблюдательское:

* angle = azimuth
* radius = altitude (внутри/снаружи линии горизонта)
* семантика = above/below horizon

**System Wheel** — системно-геометрическое:

* angle = отображение синодической фазы
* radius = нормализованная дистанция до focus
* семантика = north/south от плоскости эклиптики

Compass отвечает на вопрос «где тела в моём локальном небе?».
System отвечает на вопрос «где тела в этой орбитальной системе?».

---

## Практические примеры

`Galactic System: Sun - Mercury`

* looker: направление на Galactic Center
* focus: Sun
* targets: планеты
* результат: сравнительная phase-distance карта планетной системы вокруг Солнца

`Sun System: Earth - Moon`

* looker: Sun
* focus: Earth
* target: Moon
* результат: Earth-centered системный снимок, построенный на synod+bind геометрии

---

## Чем System Wheel не является

System Wheel — это не:

* локальное колесо видимости горизонта (семантика Horizon/Compass),
* чисто одноцелевой synod-цикл,
* чисто distance-only цикл.

Это **составное многотельное представление системы**, которое использует cycle-движки для построения единой орбитальной карты.
